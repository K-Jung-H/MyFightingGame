격투게임 입력 시스템 구조 문제 및 개선 설계안



1. 현재 구조의 문제점 (오작동 원인)



루프 불일치에 따른 입력 유실: 렌더링 루프(`Update`)에서 입력을 누적하고 물리 틱(`FixedUpdate`)에서 읽어간 직후 상태를 강제로 초기화하는 구조다. 이로 인해 틱 주기가 어긋나면 키를 유지(Hold)해도 버퍼에 빈 프레임(None)이 삽입된다.

디바운스(Debounce) 방어 무력화: 물리적 키 튕김을 방지하는 1프레임 보정 로직이 존재하나, 루프 불일치로 인해 빈 프레임이 2프레임 이상 연속 발생하면 이전 프레임 참조가 끊어져 방어에 실패한다.

느슨한 시퀀스 검증 및 커맨드 오발동: 커맨드 시퀀스 검증 시 `ExactMatch` 요구 스텝에 불일치하는 데이터가 섞여 있어도 검사를 중단하지 않고 건너뛰는 논리적 결함이 있다. 이 결함과 강제 삽입된 빈 프레임이 결합하여, 방향키를 유지하기만 해도 '더블 탭(Tap)' 커맨드로 잘못 인식된다.

네트워크 확장성 결여: 시뮬레이션 틱 연산 과정에서 로컬 기기의 하드웨어 상태를 직접 폴링한다. 이는 향후 롤백 기반 온라인 멀티플레이어 환경 도입 시 클라이언트 간 심각한 결정론적 동기화 불일치(Desync)를 초래한다.



2. 개선 설계안 (해결책)



순수 상태 스냅샷 캡처 방식으로 전환: 입력을 누적하고 비우는(Clear) 로직을 전면 폐기한다. 입력 제공자(Local Input Provider)는 매 프레임 순수한 물리적 키 눌림 상태만을 캡처하여 단일 스냅샷 형태로 전달한다.

하이브리드 입력 매니저(링 버퍼) 도입: 입력 수집 시점과 실제 틱 연산 시점을 완전히 분리한다. 수집된 스냅샷은 즉시 실행되지 않고, 설정된 입력 지연(Input Delay) 프레임만큼 더해진 타겟 틱 인덱스의 링 버퍼에 분리 저장된다.

결정론적 동기화를 위한 입력 라우팅: 오프라인/온라인 모드에 따라 로컬 입력과 원격(네트워크) 입력을 각각의 버퍼에 분배한다. 시뮬레이션 틱은 하드웨어를 직접 읽지 않고 오직 통합 버퍼에서만 패킷화된 입력을 꺼내어 연산하므로 완벽한 동기화를 보장한다.

엄격한 커맨드 시퀀스 매칭 적용: 입력 버퍼의 시퀀스 탐색 로직을 수정하여, 정확한 일치(Exact Match)가 요구되는 스텝에서 단 1프레임이라도 다른 입력이 감지될 경우 즉시 탐색을 실패 처리하도록 검증을 강화한다.

논리적 판별 및 디바운스 처리 책임 위임: 입력 수집 단계에서는 단순히 눌림 여부만 전달한다. Tap/Hold 지속 프레임 계산과 1프레임 물리적 입력 끊김 보정은 시뮬레이션 틱 내부의 트래커와 컨트롤러가 전담하여 틱 연산의 일관성을 유지한다.
