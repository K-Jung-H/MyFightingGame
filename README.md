트러블 슈팅 리포트: 입력 처리 불안정성 문제

## 트러블 슈팅 리포트: 입력 스냅샷 구조 훼손 및 복원

### 1. 문제 현상

* 방향키를 유지(Hold)하고 있을 때, 특정 방향키의 더블 탭(Tap)을 요구하는 커맨드(예: SideStep)가 의도치 않게 발동됨.
* 키보드 물리적 입력이 끊기지 않았음에도 시스템 상에서 입력이 해제되었다가 다시 눌린 것으로 판정됨.

### 2. 원인 분석

* **루프 불일치에 따른 데이터 훼손:** 렌더링 루프 주기 단위로 하드웨어 입력 지속 상태를 비트 연산으로 누적하고, 물리 루프 주기 단위로 읽어간 직후 강제 초기화하는 구조적 결함.
* **가짜 빈 프레임 삽입:** 프레임 드랍 등으로 물리 틱이 연속 실행될 경우, 하드웨어 갱신 없이 강제 초기화된 빈 값을 연속으로 읽어들임.
* **디바운스 방어 무력화:** 연속된 빈 프레임 삽입으로 인해 1프레임 릴리즈 디바운스 로직이 이전 프레임 참조를 잃어 물리적 튕김 방어에 실패함.
* **결과적 오작동:** 입력 버퍼에 쓰레기 빈 프레임 데이터가 적재되어 커맨드의 Exact Match 요구 조건 시퀀스와 일치하게 됨.

### 3. 문제 해결 접근 과정

1. **초기 가설 수립:** `GameLoopManager`와 `PlayerController` 구조 변경에 따른 오작동을 의심하여 입력 누적 및 초기화 로직, 릴리즈 디바운스의 한계, 입력 버퍼의 더미 데이터 매칭 현상을 파악함.
2. **해결 방향 모색 및 검증:** 렌더링과 물리 루프의 주기 불일치를 극복하기 위해 물리 틱 내부에서 하드웨어를 직접 폴링하는 방식을 검토함. 그러나 해당 방식은 향후 네트워크 동기화 확장 시 결정론(Determinism) 충돌을 유발함을 확인함.
3. **네트워크 확장성 고려:** 네트워크 구조와의 충돌을 막기 위해 틱 연산 내부에 하드웨어 폴링을 종속시키지 않고, 물리 프레임 시점에 해당하는 순수한 하드웨어 스냅샷 패킷을 생성하여 주입하는 방식으로 방향을 수정함.
4. **구조적 결함 심층 분석:** 분석 과정에서 `InputBuffer`의 `isExactMatchRequired` 조건이 불일치할 때 탐색을 중단하지 않는 논리적 허점을 추가로 발견함. 하지만 이는 보조적인 원인일 뿐, 근본적인 원인은 하드웨어 수집부의 누적 및 초기화에 있음을 확정함.
5. **최종 해결책 도출:** 초기의 '현재 상태 스냅샷 적용' 설계 의도가 커맨드 초기화, Tap/Hold 판정, 디바운스 등 여러 필수 논리 처리와 혼합되며 계층적으로 훼손되었음을 확인함. 수집, 보정, 기록, 평가 단계로 파이프라인의 책임을 명확히 분리하여, 수집부가 원본 데이터를 가공하거나 소거하지 않도록 하위 구조를 개편함.

### 4. 해결 방안 (스냅샷 구조로의 회귀)

* **상태(State) 데이터의 일회성 소비 금지:** 하드웨어의 눌림 상태(`isPressed`)는 소비하고 지워야 할 이벤트(Event)가 아니므로, 누적 및 강제 초기화(Clear) 로직을 전면 제거함.
* **순수 스냅샷 캡처:** 시뮬레이션 틱 연산이 실행되는 시점에 실시간으로 물리 하드웨어 상태를 폴링하여 단일 프레임 스냅샷 데이터로 반환하도록 하위 입력 제공자를 개편함.
* **루프 라우팅 수정:** 렌더링 주기 내에 존재하던 입력 누적 지시를 삭제하고, 물리 틱 내부에서 각 플레이어의 방향 보정이 완료된 실시간 스냅샷을 라우팅하여 컨트롤러에 직접 주입함.

### 5. 기대 효과 및 향후 확장성

* 빈 프레임 강제 삽입 현상이 차단되어 물리 디바운스 및 홀드 프레임 계산 로직이 정상적으로 작동한다.
* 유지(Hold) 조작 중에 발생하는 더블 탭(Tap) 오발동 현상이 원천적으로 차단된다.
* 하드웨어 상태 수집과 논리적 소비가 완전히 분리되어, 추후 멀티플레이 환경에서 로컬 입력과 네트워크 입력을 식별하고 라우팅하기 용이해진다.
* 시뮬레이션 내부 루프 로직의 수정 없이, 네트워크 입력 지연(Input Delay) 처리 및 결정론적 롤백(Rollback) 넷코드를 안정적으로 융합할 수 있는 아키텍처 기반이 확립된다.
